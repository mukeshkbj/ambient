# Scan report — 2026-09-17

Deep line-by-line audit of `src/`, `scripts/`, `test/`, `infra/` — correctness,
honest-state, and lean-code pass.

## Bugs found and fixed

| Bug | Fix |
|---|---|
| `agent.wait` used the 30 s request timeout — every OpenClaw run >30 s reported `failed` | `request()` takes a per-call timeout; `agent.wait` uses `options.runTimeoutMs` (default 15 min) |
| OpenClaw disconnect mid-run emitted `error` before `offline` landed → `failed` instead of `unknown` | `waitForRun` swallows failures when the socket is gone; the close event marks runs `unknown` |
| `sessions.subscribe` / `sessions.messages.subscribe` never called → `events: true` was half-fake | subscribed on `open` and per session, best-effort (gateways that reject still work via `agent.wait`) |
| Muse `interrupt` aborted the in-flight fetch → `ask()` overwrote `cancelled` with `failed` + marked runtime `offline` | abort returns inertly; the engine's `cancelled` stands |
| Grok Bot `interrupt` emitted `message.complete` before the engine marked `cancel_requested` → runs stuck `cancel_requested` or flashed `completed` | emit removed; the engine marks `cancelled` from the `{status:"interrupted"}` return |
| Instinct reply correlation scanned `mimeType + snippet` — the `[ambient:*]` tag lives in the Subject header, never read | correlate by the sent message's `threadId`; Subject/body tag match kept as fallback |
| Engine downgraded adapter-reported `online` to `unknown` — a successful HTTP `ask` left `/healthz` showing `unknown` for 30 s | trust `onConnectionState`; adapters only emit `online` after verified success |
| `message.complete` with `status:"cancelled"` fell into the completed branch | explicit cancelled/canceled branch |
| Stale `running` runs survived a process restart forever for HTTP adapters | `registry.startAll()` marks active runs `unknown` once at boot; discovery/replay re-establishes truth |
| `PUBLIC_BASE_URL` with a trailing slash produced OAuth `resource` `//mcp` → `invalid_target` | normalized once before use |
| `store.approval(requestId)` + `store.resolveApproval(requestId)` — dead code, and globally scoped request-id lookups (the bug class approval namespacing fixed) | deleted |
| Every new conversation titled identically → voice selection couldn't disambiguate | numbered titles (`New X conversation N`) |
| `formBody`/`jsonBody` duplicated the body-reading loop | shared `body(request, limit)` helper |
| `AppConfig.publicBaseUrl`/`runtimesFile` fields never read outside config.ts | deleted; `baseUrl` used internally for the OAuth resource |
| OpenClaw runtime start double-discovered (`connect().then(discover)` + `on("open", discover)`) | `on("open")` only |
| Stale "Link Hermes Ambient" OAuth page title | "Link Ambient" |
| ~68 lines of identical event/state listener boilerplate across the four HTTP adapters | `AssistantEvented` base class in `runtimes/types.ts`; openclaw extends it for `onEvent`/`emit` |

## Verified not-bugs (checked and left alone)

- `clearLiveSessionIds` on discover for `ephemeralSessions` adapters — correct: live ids die with the socket (hermes) or process (muse threads). HTTP adapters whose ids are durable leave the flag unset.
- OAuth `authorizationRequests`/`refreshTokens` maps expire entries on use — bounded leak, acceptable for a single-owner provider.
- `serviceMethod` serves `resources/read` to `mcp:service` — the dashboard resource is static HTML.
- `fetchReplay` epoch adoption runs in `try` and `finally` — redundant but idempotent; left alone deliberately.

## Regression tests added (6)

- Muse cancel → `cancelled` stands, no `offline`.
- OpenClaw socket drop mid-run → `unknown`, not `failed`.
- Instinct reply matched by `threadId` without a quoted tag → `completed`.
- Grok Bot interrupt → `cancelled`, no racy completion.
- `status:"cancelled"` event → `cancelled`, not `completed`.
- `startAll()` marks leftover active runs `unknown`.
